Performance
how fast this project renders AND pushes frames to every output window — the two are deliberately tied, since a slower push silently caps what the outputs actually show no matter how fast frames are made. Applies live; --fps on the command line is now just the startup default. Higher costs more CPU: try 30-60 for a light vector canvas, lower it if a heavy video canvas starts stuttering.

Sequencer

plays saved canvases in order — this is the output for the monitor windows ( Output 1/2). Only runs while the master ▶ Start is engaged; it holds its own play/pause on top of that.
adds whichever canvas is currently open in the Canvas tab as a new step at the end of the list — switch canvases first, then add. Drag a step's ⠿ handle to reorder, ✕ to remove. Each row: pick its canvas, then "display" (how long it stays on screen) and "fade in" (how long it takes to fade in when it starts — fades the previous step out through black first, then this one in; 0 = instant cut).

Transport

no steps —
⏮/⏭ jump to the previous/next step, respecting that step's own crossfade same as arriving there normally; loop restarts from step 1 after the last one instead of stopping.
